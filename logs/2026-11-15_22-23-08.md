## 1. Summary of Changes
- **Database** (migration `publishable_key_access`, applied to Meowza as version `20261115151900`):
  - `candidates`, `candidate_votes`, `projects` get `owner_id uuid default auth.uid()`.
  - RLS policies for the `authenticated` role: everyone can read; you can insert rows only as yourself, and update/delete only your own.
  - Existing rows have no owner, so through the public key they are read-only. They can still be changed in the dashboard.
  - The cache tables (`sky_positions`, `sky_cutouts`, `sky_results`) can be read, inserted and updated by any signed-in user, never deleted.
  - The `sky-cutouts` bucket allows read/upload/replace, capped at 5 MB per file, `application/octet-stream` and `image/png` only.
  - `anon` (no sign-in) still gets nothing.
- **Auth**: Anonymous sign-ins turned on in the dashboard.
- **Backend**:
  - `supabase_client.py` uses `SUPABASE_PUBLISHABLE_KEY` and signs in anonymously once per install.
  - The session is kept in `backend/.supabase-session.json` (gitignored, rewritten on every token refresh), so the install stays the same user after a restart.
  - `SUPABASE_SECRET_KEY`, if set, is still used instead and bypasses RLS.
  - When RLS refuses a change: `DELETE /api/candidates/{id}` gives 403; `PATCH`/`DELETE /api/projects/{id}` give 403 for a project someone else saved (they were 404).
- **Config/docs**:
  - `backend/.env.example` now contains the publishable key (safe to commit), so setup is just "copy it".
  - README setup, table section and file map, `docs/API.md` and the `CLAUDE.md` secrets rule updated.
- **Not changed**: The UI still shows edit/delete on projects you didn't save; clicking it shows the 403 message ("Only the person who saved this project…"). Ownership is per install (one anonymous user per backend), not per browser.
- **Accepted risk**: Anyone with the key can fill the shared cache tables and bucket with junk (but cannot delete), and all installs use the Meowza project's storage and bandwidth quota.
