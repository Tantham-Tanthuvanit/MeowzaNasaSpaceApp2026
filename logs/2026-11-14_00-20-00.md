# Codebase Modification Log — One Vote per Voter on Supabase (issue #5)

**Timestamp**: 2026-11-14 00:20:00
**Author**: Claude Code (AI Assistant) & Wut
**Branch**: skyflip-ui-features
**Action**: Ported the anti-spam voting from `master` (`fixing_spam_likes`, SQLite) to the Supabase backend: each voter counts once per candidate and can take the vote back.

---

## 1. Summary of Changes
- **Database**: `candidate_votes` gets a required `voter_id` column and a unique index on `(candidate_id, voter_id)`, so the database itself refuses a second vote from the same voter.
- **Backend**: `POST /api/candidates/{id}/vote` now needs `voter_id` (422 without it). Voting again changes nothing. `vote_type: "unvote"` removes the vote. The response has `user_voted`. `GET /api/candidates?voter_id=…` adds `user_voted` to each candidate. `voter_id` is never sent back in vote lists, because knowing someone's id would let you remove their vote.
- **Frontend**: the browser makes one random id (`skyflip_voter_id` in localStorage, nothing personal in it) and sends it with votes. The button reads "I see it too" or "Take back my vote", and the count says "including you" when you have voted.
- **Limit**: there is still no login (issue #6), so this stops repeat clicks and simple spam, not someone who clears their browser storage or calls the API with made-up ids.
