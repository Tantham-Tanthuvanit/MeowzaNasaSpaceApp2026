## 1. Summary of Changes
- **Real sky pictures**: `data_loader.py` was a simulator (random Gaussian stars seeded by RA/Dec, made-up spectra and element maps). It now queries IRSA TAP (`spherex.artifact` + `spherex.plane`) for every SPHEREx image covering a position, downloads cutouts, subtracts ZODI, reprojects each onto one north-up 6.15″/px grid, and builds one flipbook frame per survey visit (images > 10 days apart = new visit).
- **Caching (the slow part)**: one IRSA cutout takes ~10–15 s. Each is downloaded once by a background job (4 in parallel, flipbook images first, then the rest) and stored in Supabase Storage (`sky-cutouts` bucket, `.npy`) with a `sky_cutouts` row. Finished responses go in `sky_results`, and download state in `sky_positions`, so a restart resumes. While images are missing, `/api/sky-cutout` and `/api/spectrum` answer **202** with progress; the frontend polls every 3 s and shows "Downloading picture N of M from NASA…".
- **Kept because real data supports it**: detector bands, stacked, false-color RGB, difference image, shift-and-add (now on real visits; the preset-based `recommended_vx/vy`/`target_aligned` were dropped), narrow-band filters and spectral indices (from cached images whose wavelength at the spot matches), and a 102-channel spectrum (`/api/spectrum`, centre-pixel values binned into the real SPHEREx channels from IRSA's DR1 cube `properties`).
- **Removed because there is no real data**: element/molecule density maps (`/api/element-density`, `ELEMENT_DEFINITIONS`, the density renderers in `image_processor.py`).
- **Catalogs**: the old VizieR query 404s (`vizier.cds.unistra.fr/viz-bin/votable`), so the overlay had always been the fake fallback. It now queries Gaia DR3 (`gaia_dr3_source`) and AllWISE (`allwise_p3as_psd`) through IRSA TAP, flags AllWISE sources with W1−W2 ≥ 1 and no Gaia star within 3″ as brown dwarf candidates (WISE 0855 is flagged), and raises instead of inventing sources.
- **Presets removed**: `PRESET_TARGETS`, `matched_preset`, `/api/presets`, `target_preset`; frontend "Or try one of these" list, `FRIENDLY` text, `toTarget`/`targetAt`, the 5 `SEED_PROJECTS`, and the WISE 0855 default start position (the viewer now waits for a typed position). The 3 seeded SQLite candidates are gone.
- **Supabase** (`supabase/migrations/20261113161630_init.sql`, applied): `candidates`, `candidate_votes`, `projects`, `sky_positions`, `sky_cutouts`, `sky_results`, private bucket `sky-cutouts`. RLS on with no policies and all privileges revoked from `anon`/`authenticated`; only the backend's secret key can reach it. `upvotes` is now the vote count (no stored counter). Candidate ids are bigint identity (MPC export prints `SPX-000001`).
- **Projects** moved from browser localStorage to Supabase via new `/api/projects` CRUD; shared by everyone. `star`/`kind` fields (preset-only) dropped.
- **Flask deleted**: `flask_app.py`, `test_flask.py`, flask packages, `./start.sh flask`.
- **Terms of use checked**: IRSA public data has no usage restrictions (caching allowed); SPHEREx acknowledgement added; Gaia DR3 is CC BY-NC 3.0 IGO (credit, non-commercial) and stays in memory only; AllWISE credited. A "Data credits" footer is on both pages and in the README.

## 4. Follow-up fix (2026-11-13 ~23:15): slow and stuck loads in the browser
Reported: WISE 0855 loaded very slowly and Proxima Centauri (14h29m43s −62d40m46s) stuck at "0 of 14".
- **Cause 1, cache miss**: the viewer rounds RA to 0.1 s in the address bar (08h55m10.831s → 133.7950°), but positions were cached by an exact 0.0001° key (133.7951°). The browser's request was treated as a new spot and started a full 258-image download. **Fix**: `_position` reuses any cached position within half a SPHEREx pixel (3.1″).
- **Cause 2, one shared first-come queue**: every new spot queued *all* its images (for the spectrum) on 4 shared download threads, so Proxima's 14 flipbook images waited behind 258 others. **Fix**: a priority queue. Flipbook images (priority 0) always go before spectrum/filter images (priority 1). A spot's full image set is only downloaded when `/api/spectrum` or a filter band is requested. A re-request at higher priority moves an image up the queue. Images that failed after retries are skipped, so they can't block a request.
- **Cause 3**: every `/api/sky-cutout` response also ran a live Gaia + AllWISE query (2 IRSA TAP calls, not used by the site). **Removed** from that response; it stays available at `/api/catalog-overlay`.
- Tests: 3 new queue tests; **25 passed** with `LIVE_TESTS=1`.
- Re-tested on a fresh server: WISE 0855 as the browser sends it → **0.37 s / 0.26 s** (cache hit). Proxima Centauri first load → 202 with progress 0→14, real frames at **55 s** (2026-03-09, 03-27, 07-28, 09-01; 379 images exist there). Exactly 14 cutouts were downloaded.
- Left over: a duplicate position row `133.7950-7.2451_5` (partial cache, created by the old exact-key lookup). It's harmless, since the older complete row wins the nearby lookup, and can be deleted.
